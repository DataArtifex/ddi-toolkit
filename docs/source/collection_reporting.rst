Multi-Dataset Collection Reporting & AI Storytelling
====================================================

The **Multi-Dataset Collection Reporting & AI Storytelling** framework in ``dartfx.ddi.harmonizer`` (modules ``reporting``, ``reporting_html``, and ``llm``) provides end-to-end longitudinal comparison, variable-cascade harmonization auditing, interactive visual exploration, and AI-powered narrative generation across collections of **two or more related DDI datasets** (such as annual survey waves, repeated cross-sections, or topical series).

.. contents:: Table of Contents
   :local:
   :depth: 2

Architecture: Two-Phase Reporting Workflow
------------------------------------------

The reporting pipeline cleanly separates deterministic metadata analysis (**Phase 1**) from LLM narrative synthesis (**Phase 2**), caching intermediate per-survey artifacts and saving ``collection_report.json`` so you can iterate rapidly on narrative styles and models without re-parsing XML files:

.. code-block:: text

   +--------------------------------------------------------------------------------+
   |        INPUT COLLECTION (2+ DDI-Codebook .xml or DDI 4.0 RC1 .ddi40.json)      |
   +--------------------------------------------------------------------------------+
                                           |
                                           v
   +--------------------------------------------------------------------------------+
   |                    PHASE 1: PROGRAMMATIC ANALYSIS & CACHING                    |
   |                                                                                |
   |  Stage 1 — Per-Survey Deduplication & DDI-L Upgrade (load_survey_bundle)       |
   |    - Auto-detects DDI-Codebook (1.2.2 / 2.5 / 2.6) or DDI 4.0 JSON             |
   |    - Upgrades & deduplicates Categories, CodeLists, Questions & RepVars         |
   |    - Persists cache/<file>.<sha12>.v2.bundle.json, .ddi40.json, .stats.json    |
   |                                                                                |
   |  Stage 2 — Cross-Survey Resource Deep Dives (analyze_collection)               |
   |    - Categories: typos, inclusive writing, routing artifacts, sentinel audit   |
   |    - CodeLists: inclusive vs. exclusive of sentinels, recodes, permutations    |
   |    - Questions: spelling drift, shared stems, same prompt / different scale    |
   |    - Variable Cascade: Instance -> Represented -> Conceptual + False Friends   |
   |                                                                                |
   |  Stage 3 — Longitudinal Evolution                                              |
   |    - Chronological wave ordering (auto / input), adjacent transitions & matrix |
   +--------------------------------------------------------------------------------+
             |                             |                             |
             v                             v                             v
   collection_report.json        collection_report.md       collection_explorer.html
             |
             v
   +--------------------------------------------------------------------------------+
   |                PHASE 2: AI NARRATIVE & STORYTELLING (narrate)                  |
   |                                                                                |

   |             | Template fallback (deterministic-narrator-v1)                    |
   |  Styles:    technical (stories/)   | journalistic (stories_journalistic/)      |
   +--------------------------------------------------------------------------------+
             |
             v
      story_highlights.md · story_longitudinal.md · story_quality-anomalies.md
      story_harmonization-playbook.md · all_stories.md · prompts/*.prompt.txt

Supported Input Formats & Chronological Wave Ordering
-----------------------------------------------------

``resolve_input_files(inputs, pattern="*.ddic.xml")`` accepts a mix of individual DDI file paths and directories:

* **DDI-Codebook XML** (``1.2.2``, ``2.5``, ``2.6``): Flavor is detected automatically from XML namespaces and ``codeBook/@version``. Summary statistics (``sumStat``), category frequencies (``catStat``), missing-value attributes (``missing="Y"`` / ``isMissing``), question elements (``preQTxt``, ``qstnLit``, ``postQTxt``, ``ivuInstr``), universes, and variable numeric/text formats are extracted directly.
* **DDI 4.0 RC1 JSON** (``*.ddi40.json``): Native ``ItemContainer`` documents generated by the toolkit's DDI-Lifecycle converter.
* **Chronological Wave Ordering**: ``order_by="auto"`` extracts four-digit years (e.g., ``2013``–``2025``), ``wave``/``vague`` numbers, and ``study_id`` / title / filename metadata to sort waves chronologically; pass ``order_by="input"`` to preserve CLI or list order.
* **Disk Caching**: Per-survey bundles and upgraded DDI 4.0 JSON artifacts are cached in ``<output_dir>/cache/`` keyed by SHA-256 content digest and ``CACHE_SCHEMA_VERSION`` (``v2``). Use ``--refresh-cache`` (or ``refresh_cache=True``) to recompute cached bundles.

Phase 1: Programmatic Collection Comparison
-------------------------------------------

Running ``analyze_collection(files, ...)`` produces a frozen Pydantic :class:`~dartfx.ddi.harmonizer.reporting.CollectionComparisonReport` organized into three analytical stages:

Stage 1: Per-Survey Deduplication Summary (``SurveyDeduplicationSummary``)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Evaluates intra-survey redundancy when upgrading raw survey variables into canonical DDI-Lifecycle / DDI 4.0 building blocks:

* Raw vs. deduplicated counts and reduction percentages for **Represented Variables**, **Questions**, **CodeLists**, and **Categories**.
* Counts of **explicitly flagged sentinels** (e.g., ``missing="Y"``), **inferred undocumented sentinels** (common French/English non-response labels lacking a missing flag), and **routing filter artifacts**.
* Distribution of value representation domains (e.g., code, numeric, text, datetime) and variable statistics coverage.

Stage 2: Cross-Survey Resource Deep Dives
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

.. list-table::
   :widths: 22 78
   :header-rows: 1

   * - Section Model
     - Analytical Capabilities
   * - ``CategoryAnalysisSection``
     - Global exact vs. normalized unique category counts; **inclusive writing transitions** (e.g., ``Retraité(e)`` :math:`\to` ``Retraité·e``); typographical slips (``typographical_variants_count``); near-match harmonization pairs; **sentinel missingness auditing** (``EXPLICIT_SENTINEL``, ``INCONSISTENT_MISSING_FLAG``, ``UNDOCUMENTED_SENTINEL``); and accidental **routing filter artifacts** leaked into respondent answer labels (e.g., ``b11a-b11b-b12a-...``).
   * - ``CodeListAnalysisSection``
     - Dual-mode matching **inclusive vs. exclusive of sentinel/missing values**, quantifying exact additional merges gained when decoupling sentinels from substantive response scales (``additional_merges_when_excluding_sentinels``). Detects ``EXACT_FULL`` reuse, ``SUBSTANTIVE_EXACT_SENTINEL_DIFF`` (same scale, shifted missing codes such as ``6/9`` :math:`\to` ``6666/9999``), ``CATEGORIES_EXACT_CODES_DIFFERENT`` recodes with explicit ``recode_map`` dictionaries, ``PERMUTATION`` orderings, ``LABEL_VARIANT_SAME_CODES``, and partial-overlap ``SCALE_EVOLUTION``.
   * - ``QuestionAnalysisSection``
     - Exact and normalized question reuse across waves; spelling, typographical, and inclusive-writing drift; ``SAME_QUESTION_DIFFERENT_REPRESENTATION`` (identical wording backed by changed code lists, ranges, or sentinel regimes); near-match candidates; and **shared-stem multi-item batteries** (``QuestionBatterySummary``).
   * - ``VariableCascadeSection``
     - Implements the DDI variable cascade (**InstanceVariable** :math:`\to` **RepresentedVariable** :math:`\to` **ConceptualVariable**). Synthesizes multi-faceted ``RepresentedVariable`` signatures incorporating CodeList, canonical data type, numeric min/max range, decimals, unit, text length, and universe. Identifies shared substantive clusters across waves, **representation drift lineages** (``RepresentationDriftFinding``), and **"False Friend" variable names** (``FalseFriendVariableFinding``) where an identical physical column name measures different concepts or refreshed panel weights across waves.

Stage 3: Longitudinal Evolution (``LongitudinalAnalysisSection``)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

* **Wave-to-Wave Transitions (``WaveTransitionRecord``)**: For every adjacent transition :math:`W_{t-1} \to W_t`, computes concept counts, exact representation retention, substantive retention with sentinel drift, representation/text drift retention, returning concepts from earlier waves, newly introduced concepts, dropped concepts, and overall continuity rate percentage.
* **Continuity Matrix (``LongitudinalLineageRow``)**: Classifies every harmonized conceptual lineage into persistence tiers:

  * ``CORE_PERMANENT`` (:math:`\ge` 80% of waves)
  * ``ROTATING_MODULE`` (3+ waves, <80%)
  * ``PAIR_WAVE`` (2 waves)
  * ``SINGLE_WAVE`` (1 wave only)

  Each cell records per-wave status: ``EXACT (<var>)``, ``SENTINEL_DIFF (<var>)``, ``DRIFT (<var>)``, or empty.

Interactive HTML Collection Explorer (``collection_explorer.html``)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

``render_collection_explorer_html(report, output_path=...)`` writes a standalone, zero-dependency HTML5 explorer with light/dark theme toggle, one-click JSON export, live filtering, and **six interactive tabs**:

1. **Overview & Upgrade**: Executive KPI cards and Stage 1 per-wave deduplication table.
2. **Longitudinal Continuity**: Adjacent wave-transition metrics and searchable Continuity Matrix filterable by persistence tier and drift status.
3. **Questions Explorer**: Switchable views for spelling/inclusive/typo variants, same-question/different-representation pairs, near-match candidates, and shared-stem batteries.
4. **CodeLists & Sentinels**: Interactive comparison across substantive-exact/sentinel-different divergences, recoded value maps, label variants, scale evolutions, and top reused scales.
5. **Categories & Missingness Audit**: Variant explorer, sentinel flag consistency audit, near-matches, and leaked routing artifact viewer.
6. **Variable Cascade & False Friends**: Shared ``RepresentedVariable`` clusters, concept representation-drift lineages, and false-friend variable name collision detector.

Phase 2: AI-Powered Narrative & Story Generation
------------------------------------------------

``generate_all_stories`` and ``generate_collection_story`` turn a saved ``CollectionComparisonReport`` into publication-ready Markdown stories backed strictly by compact, lossless evidence slices from ``build_compact_evidence_slice``.

Story Types (``StoryKind``)
~~~~~~~~~~~~~~~~~~~~~~~~~~~

* ``highlights`` (``story_highlights.md``): Executive highlights / flagship archival dispatch covering deduplication gains, missing-data divides, key recodes, and core stability.
* ``longitudinal`` (``story_longitudinal.md``): Wave-by-wave continuity chronicle contrasting stable spines against major questionnaire redesigns and measuring-stick shifts.
* ``quality-anomalies`` (``story_quality-anomalies.md``): Investigative audit spotlighting typos, inclusive-writing transitions, vanishing sentinel flags, leaked routing filters, and false-friend variable names.
* ``harmonization-playbook`` (``story_harmonization-playbook.md``): Actionable methodological field guide with concrete recode rules, sentinel mappings, and scale reconciliation strategies.
* ``all_stories.md``: Combined compilation of all generated stories, plus optional prompt audit logs under ``prompts/*.prompt.txt``.

Narrative Styles (``NarrativeStyle``)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

* ``technical`` (default, ``--style technical``): Writes crisp metadata-architect specifications, DDI terminology, and harmonization recipes into ``<output_dir>/stories/`` at temperature ``0.2``.
* ``journalistic`` (``--style journalistic``): Writes long-form, human-centered data journalism (vivid headlines, standfirst deks, plain-prose explanations of schema findings, bilingual quotes, compact tables) into ``<output_dir>/stories_journalistic/`` at temperature ``0.55``, keeping both editions side-by-side without overwriting.

LLM Providers & Default Models (``LLMProvider``)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

.. list-table::
   :widths: 18 26 56
   :header-rows: 1

   * - Provider
     - Default Model (``DEFAULT_MODELS``)
     - Connection & Behavior Notes
   * - ``ollama``
     - ``qwen3.8:27b-mlx``
     - Local Ollama server (``OLLAMA_HOST`` or ``http://localhost:11434``). Auto-discovers installed local models via ``/api/tags`` when ``model=None``. Calls native ``/api/chat`` with ``think=False`` (or ``/v1/chat/completions`` with ``reasoning_effort="none"`` when ``--base-url`` ends with ``/v1``), strips inline ``<think>`` blocks, and compacts LLM-padded Markdown tables.
   * - ``openai``
     - ``gpt-4o-mini``
     - Explicit OpenAI Chat Completions API (``OPENAI_API_KEY``) or any OpenAI-compatible server via ``--base-url`` / ``OPENAI_BASE_URL`` (e.g., vLLM, LM Studio, OpenRouter).
   * - ``gemini``
     - ``gemini-3.8-flash``
     - Google Gemini REST API (``GEMINI_API_KEY`` or ``GOOGLE_API_KEY``). Filters out internal Gemini ``"thought": true`` parts before assembling output Markdown.
   * - ``anthropic``
     - ``claude-3-5-sonnet-latest``
     - Anthropic Messages REST API (``ANTHROPIC_API_KEY``).
   * - ``template``
     - ``deterministic-narrator-v1``
     - Zero-network, deterministic evidence-grounded generator used explicitly or automatically as fallback (when ``fallback_to_template=True`` and an endpoint is unreachable).

CLI Usage Reference
-------------------

All reporting workflows live under the ``dartfx-ddi harmonizer`` CLI group.

Phase 1 (Programmatic Reports Only):

.. code-block:: bash

   # Scan a directory matching '*.ddic.xml' and sort waves chronologically
   uv run dartfx-ddi harmonizer report /path/to/surveys \
     -o ./report_out

   # Customize file glob pattern, title, wave ordering, and cache refresh
   uv run dartfx-ddi harmonizer report /path/to/surveys \
     -p "*.xml" \
     -o ./report_out \
     -t "ELIPSS Annual Survey Collection" \
     --order-by auto \
     --refresh-cache

Phase 2 (Generate or Re-Generate Narratives from ``collection_report.json``):

.. code-block:: bash

   # Journalistic stories using local Ollama (defaults to qwen3.8:27b-mlx or auto-detected model)
   uv run dartfx-ddi harmonizer narrate ./report_out/collection_report.json \
     -p ollama \
     -S journalistic

   # Specify an explicit local model and write to a separate subfolder
   uv run dartfx-ddi harmonizer narrate ./report_out/collection_report.json \
     -p ollama \
     -m gemma4:e2b-mlx \
     -S journalistic \
     --stories-dir stories_journalistic_gemma4

   # Use Google Gemini (uses GEMINI_API_KEY; defaults to gemini-3.8-flash)
   uv run dartfx-ddi harmonizer narrate ./report_out/collection_report.json \
     -p gemini \
     -S journalistic

   # Use OpenAI or a custom OpenAI-compatible endpoint
   uv run dartfx-ddi harmonizer narrate ./report_out/collection_report.json \
     -p openai \
     -m gpt-4o-mini \
     --base-url https://openrouter.ai/api/v1 \
     -S journalistic

   # Generate a single story using deterministic zero-network templates
   uv run dartfx-ddi harmonizer narrate ./report_out/collection_report.json \
     -p template \
     -S journalistic \
     -s quality-anomalies

Combined Phase 1 + Phase 2 in One Command:

.. code-block:: bash

   uv run dartfx-ddi harmonizer report /path/to/surveys \
     -o ./report_out \
     --narrate \
     --provider gemini \
     -S journalistic

.. note::
   On ``harmonizer report``, ``-p`` is shorthand for ``--pattern``; always spell out ``--provider`` when pairing with ``--narrate``. On ``harmonizer narrate``, ``-p`` is shorthand for ``--provider``.

Python SDK Usage
----------------

.. code-block:: python

   from pathlib import Path
   from dartfx.ddi.harmonizer import (
       LLMConfig,
       LLMProvider,
       NarrativeStyle,
       StoryKind,
       analyze_collection,
       generate_all_stories,
       render_collection_explorer_html,
       resolve_input_files,
   )

   # 1. Discover and analyze 2+ DDI datasets (Phase 1)
   out_dir = Path("report_out")
   files = resolve_input_files(["/path/to/surveys"], pattern="*.ddic.xml")

   report = analyze_collection(
       files=files,
       title="Longitudinal Survey Collection Audit",
       cache_dir=out_dir / "cache",
       order_by="auto",
   )

   # 2. Persist Phase 1 outputs
   out_dir.mkdir(parents=True, exist_ok=True)
   (out_dir / "collection_report.json").write_text(report.model_dump_json(indent=2), encoding="utf-8")
   (out_dir / "collection_report.md").write_text(report.to_markdown(), encoding="utf-8")
   render_collection_explorer_html(report, output_path=out_dir / "collection_explorer.html")

   # 3. Generate Phase 2 journalistic stories via Gemini 3.8 Flash (or Ollama / OpenAI / Template)
   cfg = LLMConfig(
       provider=LLMProvider.GEMINI,  # Defaults to gemini-3.8-flash
       style=NarrativeStyle.JOURNALISTIC,
   )
   stories = generate_all_stories(
       report,
       output_dir=out_dir,
       config=cfg,
       story_kinds=[
           StoryKind.HIGHLIGHTS,
           StoryKind.LONGITUDINAL,
           StoryKind.QUALITY_ANOMALIES,
           StoryKind.HARMONIZATION_PLAYBOOK,
       ],
   )
   for st in stories:
       print(f"{st.story_kind.value}: generated by {st.provider_used}/{st.model_used}")

Key Data Models & Entry Points
------------------------------

.. list-table::
   :widths: 34 66
   :header-rows: 1

   * - Symbol
     - Role
   * - ``resolve_input_files`` / ``load_survey_bundle``
     - Expand CLI/directory file inputs and load/cache normalized per-survey metadata bundles (including DDI-L 4.0 upgrade artifacts).
   * - ``analyze_collection``
     - Execute Stage 1–3 comparison and return ``CollectionComparisonReport``.
   * - ``CollectionComparisonReport``
     - Root Pydantic report model containing ``surveys``, ``categories_section``, ``codelists_section``, ``questions_section``, ``variables_section``, and ``longitudinal_section``, with ``.to_markdown()``.
   * - ``render_collection_explorer_html``
     - Render the 6-tab interactive standalone HTML explorer.
   * - ``LLMConfig`` / ``LLMProvider`` / ``NarrativeStyle`` / ``StoryKind``
     - Phase 2 configuration enums and Pydantic config model.
   * - ``generate_collection_story`` / ``generate_all_stories``
     - Produce single or complete sets of Phase 2 Markdown narratives (``GeneratedStory``) and compiled ``all_stories.md``.
